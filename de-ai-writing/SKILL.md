# 去除 AI 味与提示词精简技能 (de-ai-writing)

本技能提炼自 GPT-6 官方指南中的行为校准规范与提示词最佳实践，包含两大核心能力：
1. **文本/文章去 AI 味**：一键剔除刻板过渡、总结套话、空洞形容词与假装深刻的自问自答。
2. **Agent 提示词优化 (Prompt Optimizer)**：校准智能体行为，让 Agent 更主动交付可审阅成果、杜绝无意义打断、精简无效防御性测试。

---

## 模式 1：文本/文案去 AI 味 (De-AI Style)

当用户提供一段文案、报告、文章、邮件并要求“去 AI 味”、“润色”、“去掉套话”或“写得像真人”时，严格执行以下清洗规则：

### 1. 禁用词与套话黑名单
坚决删除或替换以下高频“AI 味”表达：
- **空洞过渡/总结词**：
  - 中文：`值得注意的是`、`深入探讨/深挖`、`不可否认的是`、`总而言之/简而言之`、`赋能/抓手/打法`、`底层逻辑/心智模型`、`正如前面所提到的`。
  - 英文：`Bottom Line:`、`delve`、`foster`、`leverage`、`it's worth noting`、`importantly`、`In short:`、`The simplest mental model is:`。
- **机械句式**：
  - **自问自答**（如：“为什么这么做？答案很简单……”）
  - **伪深刻对比句**（如：“这不仅是关于 X，更是关于 Y……”、“是 X，而非 Y……”）
  - **自我设限/解释声明**（主动声明“我不会做什么”、“我将保持什么不变”、“我是如何分类的”）
  - **生硬造词/虚假专业词**（如自造复合修饰标签、滥用破折号加长定语）

### 2. 重构原则
- **主动句 + 动词主导**：用朴素、具体的动词直接陈述动作与结果。
- **结论先行**：第一句话直接交代核心事实或决定，随后补充必要背景。
- **克制使用列表**：不要动辄分 1、2、3、4 点，除非内容确实是严格的并列项、操作步骤或对照表；优先使用连贯清晰的自然段落。

## 模式 2：Agent 提示词优化 (Agent Prompt Calibration)

当用户编写或优化系统提示词（System Prompt）、Skill 规则、角色设定或工作流时，按需注入以下标准指令模块：

### 模块 A：自主推进与交付可审阅成果 (Autonomous Action)
> 解决痛点：Agent 总是问“你想让我做吗？”、“我可以帮你做这个”，或者只给建议不执行。

```markdown
当用户用“能不能……”“我想……”“帮我……”等表达提出行动请求时，请将其视为执行工作并采取行动的指令。不要只确认自己有能力完成（如回答“可以”），也不要停留在提出计划或表示愿意继续。
在向用户提出澄清问题之前，请先完成上下文中已经授权、且能使拟议行动具体化并可供审阅的必要工作（如准备好完整文件草稿、完成只读排查、做好环境准备），让用户批准成为最后一步。对于可逆任务、只读操作、常规修复，无须反复请求许可。
不要因为假设性的风险，主动添加冗长的警告、免责声明或未经要求的多层审批流程。
```

### 模块 B：指令冲突透明化 (Instruction Precedence)
> 解决痛点：加载多个 Skill 或规约后，Agent 行为混乱、隐蔽卡住。

```markdown
用户实时指令优先于预置技能中的指导建议。如果明确的用户指令与技能说明冲突，优先遵循用户指令。
如果某项内部规范或技能使你不得不暂停、请求额外确认或无法完成用户要求的工作，请直接指出相关规范或文件的具体条款，并简要说明适用原因，保持行为透明。
```

### 模块 C：按需测试与避免过度工程 (Calibrated Testing)
> 解决痛点：改一行代码，模型写了 200 行重复测试或陷入死循环。

```markdown
对于可逆、影响较小的变更，不要编写仅仅复刻实现逻辑的无意义测试。
仅运行与变更相适应的测试与验证检查。验证通过后，除非出现新变更或失败，否则不要无休止扩大或重复测试范围，直接推进任务至最终交付。
```

## 触发与调用方式

- **/de-ai <文本>**：清洗指定文本的 AI 腔调，输出干练朴素版本。
- **优化提示词 / 帮我改下这个 System Prompt**：审查提示词，剔除模糊描述，植入自主推进和精准输出规则。
