# 默认草稿保存与成品交付

## 现成工具

优先读取当前环境已安装的 `baoyu-post-to-wechat/SKILL.md`，使用其保存能力；本机位置为 `/Users/joker/.codex/skills/baoyu-post-to-wechat/SKILL.md`。其他 Agent 按自身技能目录解析，不把本机绝对路径当成通用前提。调用前读取其项目级和用户级 EXTEND.md、多账号配置及对应模式说明。

文章 API 脚本为 `scripts/wechat-api.ts`，调用 `draft/add`；浏览器文章脚本为 `scripts/wechat-article.ts`，贴图脚本为 `scripts/wechat-browser.ts`。先核实当前版本参数和行为再调用，不能因参数名含 submit 就推断是保存或正式发表。只执行草稿动作，不调用正式发表接口。

## 账号和排版

- 绑定账号配置中的 API 别名或现有浏览器登录态，核对后台公众号身份；不能采用工具默认账号覆盖工作流账号。
- 有有效 API 配置时可复用；未配置则优先沿用现有已登录浏览器及可用自动化，遵守用户浏览器选择，不擅自启动 Chrome 或切换账号。首次必要配置缺失时具体说明缺什么，不声称已接通。
- 素琴等已有固定排版的账号使用已经验收的 HTML 输入路径，不让工具默认主题重新渲染破坏版式。区分工具对现有 HTML 与 Markdown 的不同处理，必要时读取相关脚本和说明。
- 上传文内图片并确认持久可访问的微信图片地址；本地路径不得作为后台图片交付。

## 保存、恢复与验收

每篇或每条单独记录稿件ID、账号、版本、草稿标识及保存时间，保存响应不确定先查已有草稿，避免重试造出重复草稿。成功后用后台重新打开或 API 草稿读取核对标题、正文、摘要、图片、顺序及账号；视觉排版仍需实际预览。保存与回读分开记录，回读失败不得写“回读通过”。

未生图模式继续处理文字和排版。有合适已确认图可复用；后台必填图缺失时保持配图待补状态，供其他 Agent 续接。生图工具缺失、登录过期、API 权限不足等阻塞不得虚构成功；成品保存在项目，面向用户只报尚缺的一步与必要配合。

文章与贴图使用各自入口和记录，不把文章编辑器插入多张图片当成原生贴图。已有文章转贴图需检查实际后台入口，不机械把正文截图分页。

最终向用户展示定稿标题、成品预览及“已保存并回读／保存待回读／未保存及原因”。检查 JSON 和素材台账留在项目内部，不要求用户自行组装成品。
