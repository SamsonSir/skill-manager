# 新旧角色共用的视觉建档规范

## 通用必经流程
所有角色均执行：绑定账号与角色 → 读取身份/场景资产 → 查看近期文章与贴图 → 决定场景、衣着、配饰和机位 → 生成 → 分别验收人物、环境连续性、真实性和规格 → 更新记录。执行时不能因为是新账号省略。已有账号复用当前资产，缺字段只补缺项，不重新设计已确认角色。

## 每角色独立资产
账号配置指向以下实际文件，路径可以适应项目结构：

- `identity.json`：账号ID、角色ID、版本、确认状态、主脸与其他身份参考路径及哈希。无已确认主脸时保持待确认，不声称人物已锁定。
- `scene_registry.json`：场景ID、参考图、确认/公开状态、固定家具及空间关系、允许变化项。没有室内图时允许空登记；首次采用室内图后登记，后续同空间复用。
- `配图使用记录.md`：稿件、图片、候选/已选/已发布状态、内容日期、场景ID/类型、衣着、配饰、机位、参考和验收。空记录表示尚未制作，不能编造历史。
- 角色视觉配置：服装审美和类别、换衣频率、配饰偏好、自拍/他拍倾向、允许场景类型、成像风格、尺寸；并关联实际穿搭参考。

同一账号多个角色各有独立身份与用图记录；共同居住场景只有明确建立共享关系后才可共用。不得通过名字相似、上一轮选择或默认账号借用资产。

## 默认与个性化
用户最新要求将以下原则用于未来角色：保持已建立室内环境、主动检查室内外和机位重复、正常换衣、多样穿搭、配饰自然可信。未另行指定时，换衣以同套通常不连续超过两个内容日为起始默认，配饰以不戴为主、偶尔少量为起始默认；同一天同次活动保持一致。日期未知按近期用图检查，不伪造日期。新角色明确设定可覆盖这些可调参数。

黄色碎花、素琴的主脸、沙发、女性年龄、具体服装审美与固定排版不是通用默认。新角色应从其已确认定位与参考推导这些值；确实缺少影响成品的关键决定才询问。

## 必要检查
生成前确认所有读取资产属于当前账号/角色；出现人物时执行身份校验并实际查看身份图；重复室内空间须实际加载场景参考。生成后对照参考检查，无法判断则标待验收，不能凭脚本通过宣称视觉一致。记录缺失时先检查现有资产并回填已知事实；无证据字段明确未知，不以空历史为由任意换家具或身份。
