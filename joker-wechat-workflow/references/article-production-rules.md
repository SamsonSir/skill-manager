# 文章模式内部制作与验收规则

默认终点以入口新版为准：用户未取消保存时，制作配图与固定排版后必须执行草稿保存及回读，具体见 `draft-delivery.md`。旧文中“用户明确要求草稿时”不再表示每次需要另行授权。内部验收材料归档，用户只接收成品和实际草稿结果。

## 账号隔离
每次显式绑定用户指定的账号项目，读取其 AGENTS.md、账号配置.md、人物定稿、语气样本及当前进度。账号不明且存在多个候选才询问，不能默认沿用上一账号。人物、受众、语气、选题范围、视觉、事实和权限均来自当前账号配置；缺失就标明，不回退为素琴或其他账号。所有输出存入当前账号项目。不同账号不共享未经授权的私有素材。

## 执行
读取账号指定的教程和原文对标；沿当前阶段续接，复用已确认稿件，不为演示重新研究赛道。
先读取账号配置指向的角色创作合同；缺失时停止正文生成并列出缺失字段，不能用上一账号或模型印象代替。合同至少明确账号ID、人物定稿与语气锚点、事实策略、允许的素材类型、不得自动补全的履历字段。按入口 Skill 路由依次读取 `modules/topic.md`、`modules/writer.md`、`modules/title.md`；它们是内部阶段规范，不是面向用户的独立入口。每阶段记录输入、结果、检查证据和未验证项。
通用能力按需路由：写作与改稿可调用 human-writing、humanizer；标题可调用 gzh-title-strategist；复杂公众号 HTML 可调用 gzh-design。外部 Skill 的固定模板、候选数量、标点禁令、自动目录、章节编号、关键词装饰、签名和 CTA 都不是账号默认规则，只有账号配置明确允许时才采用。
视觉优先复用当前环境可用的 imagegen、baoyu-cover-image 或 baoyu-article-illustrator；排版优先已装 space-wechat-layout 或 baoyu-markdown-to-html，使用前读取实际技能文件。账号配置覆盖通用风格默认值；不静默修改上游技能。
用主题选择画面，不把头像画风强制推广到封面。画面出现重复人物时，先读取当前账号配置指向的角色视觉身份包；每张图都把包内已确认主脸作为第一张身份输入，摄影、穿搭和场景参考只承担各自属性。不得把上一张候选生成图继续当身份源，也不得借用其他账号人物。没有身份包或主脸文件时，改用无人场景或先建立该账号身份锚点，并标“未建立跨图一致性”，不宣称锁定。已公开出现的室内场景必须建立独立场景清单，记录场景ID、参考图、公开状态和必须保持的家具／墙面／软装；再次使用同一室内空间时，场景参考必须随身份图一同传入，并逐项验收固定家具。仅凭文字描述“同一客厅”不得通过。未加载场景锚点却重新生成家具的图片视为穿版，不得入库。同一房间、桌面需用已确认参考图及场景编号编辑生成；新场景先作为候选，不能凭生成结果补写真实履历。
封面画布是硬门禁，不由生图模型自由决定，也不能把平台常见横图规格擅自当成账号偏好。必须先读取当前账号配置中的方向、宽高比和精确像素；配置缺失时才向用户确认。生图原图可更大，但进入项目成品前必须按主体安全区裁切为配置规定的精确像素，并运行 `scripts/check_cover_dimensions.py --image <成品> --width <配置宽度> --height <配置高度>`。尺寸不符、仅在提示词中写了比例、或只凭肉眼认为接近，均不得标为封面完成。人物脸、手和主题物件必须位于裁切安全区，裁切后再次目视验收。
排版不改已确认正文。调用总工作流且用户没有明确指定提前终点时，正文和视觉通过后必须继续到账号固定排版，不能把排版当成可选优化。账号已有排版模板时直接复用，不重新选主题；只有账号没有模板或用户明确要求改版时才调用通用排版主题。交付标题、摘要、封面、图文预览、富文本复制按钮、原图和可编辑稿。运行 `scripts/validate_layout.py --article <最终正文.md> --preview <排版预览.html>`，确认正文逐段完整且复制区域不含按钮、脚本、工具栏；失败不能显示成功。本地路径图片不能当作已可在微信长期显示。
使用 gzh-design 时先按账号已确认样式选择或定制主题，并关闭不适合该账号的自动装饰；必须通过其 HTML 校验，再用微信实际粘贴和草稿回读验收。安装成功不等于该主题已适配当前账号。
验收区分本地渲染、剪贴板、微信粘贴、保存后预览、正式发布、真实反馈。不能用本地测试替代微信证据。按当前发布权限停止，手动发布时交付给用户并记录待发布，不调用发布接口。没有发布就不能填阅读量或发布时间。
复盘从实际反馈提出下一篇，不固定章节或连写数量。

## 正文编辑验收
正文完成后按 writer 的实际改稿流程检查，再制作标题和视觉。脚本是辅助检查，不是宿主自动执行的拦截器；它不验证语义真实性或文风，Agent必须执行内容审核，不能把脚本返回PASS称为文章已合格。

1. 在稿件目录保存 `正文事实账本.json`。逐项登记正文中的第一人称经历、人物履历、具体对话、引语及可核外部事实，记录正文段落、主张类型、来源类型和可定位来源。纯观点可以登记为 `opinion`，但不能把具体动作、物件、次数、日期、地点或过去习惯归为纯观点。
2. 先完成 writer 规定的段落增量、情感表达和重复说理检查，修正具体问题，再在稿件目录保存 `角色风格验收.json`。必须从最终正文引用证据，对照角色合同和认可样文检查立场、说话位置、具体程度、语言节奏、收尾方式和近期结构重复。每项只能为 `pass` 或 `fail`；没有正文证据、没有实际读取锚点或不确定时写 `fail`，不能凭“感觉像”通过。
3. 完成一次与生成过程分离的逆向审稿：只从最终正文重新提取事实主张和风格证据，再与账本、角色合同、素材及近期稿件逐项核对。不得复用写作时的“我没有编造／我保持了文风”结论作为证据。
4. 运行 `scripts/validate_article_packet.py --article <正文> --claims <事实账本> --style <角色风格验收>`。脚本失败时状态只能是“正文待修订”，不得进入标题定稿、配图、排版、草稿或发布。
5. 事实策略为 `source_bound` 时，第一人称经历、履历、对话和引语必须有可定位来源。内部写“文学创作示例”不能把公开正文中的仿真亲历变成已核实事实；只有账号合同明确采用连续虚构人物、且公开呈现方式已获确认时，才可使用 `explicit_fiction`。
6. 内容卡的六项检查必须引用两个验收文件和脚本结果。正文与内容卡矛盾时以正文为准，不能勾选通过。自查通过只代表编辑门禁通过，不代表用户认可或平台效果。

## 排版门禁
1. 读取账号配置中的固定模板、字体、字号、行高、颜色、段距和允许的强调方式；不得用通用技能默认目录、编号、逐段高亮、签名或CTA覆盖账号模板。
2. 从最终生效正文生成干净富文本和带复制按钮的预览页。复制区域只包含正文排版；标题、摘要、封面说明、工具栏与脚本放在复制区域外。
3. 运行 `validate_layout.py`，再实际打开预览检查移动端宽度、长段可读性、强调数量和封面展示。工具栏能显示不等于复制载荷正确。
4. 用户明确终点为草稿箱时，必须把排版后的富文本粘贴进后台，保存后重新打开回读；本地预览不能替代草稿回读。

事实账本和风格验收格式见 `references/article-claims.md`。没有人物亲历素材时仍可写观点、阅读问题、普遍观察或有来源的第三人称材料；应缩小题目或改变叙述位置，不能用虚构琐事补足“人味”。

用户明确将终点设为草稿时，可按授权保存并重新打开核验正文、标题、摘要、封面与声明；记录草稿状态，不称已发表。已有页面自动保存也要如实记录。

终点早于草稿时（如只到正文、只到贴图文案），按用户指定的范围完成并停手；未做的配图、排版、后台与发布逐项写入待办，状态用「XX完成，XX待制作」如实标记，并在账号项目的当前进度和角色知识库各留一条可回填的记录。不得把未做的环节写成已完成，也不得因终点提前而省略内容卡与编辑检查。

## 跨会话人物校验（2026-09-17）
每个角色项目保存独立 identity.json（account_id、character_id、version、status=confirmed、references有序列表、retired_identity_files）。每条reference记录role、相对清单路径path及sha256；第一条必须为primary_identity，其余身份图须有用户确认依据。不得从“摄影真实感获认可”推导“脸部身份获认可”。
生成人物前运行 joker-wechat-workflow/scripts/check_identity.py --manifest <当前角色清单绝对路径> --account-id <当前账号ID>；失败先修正绑定，不能猜图继续。成功后实际查看返回的身份图，按顺序传入生图工具；摄影参考单列在后。每次调用记录角色ID、清单版本、实际传入路径和提示词。
出图后与主脸及已确认侧面图逐项目视比较脸型、眼型/眼距、鼻唇比例、下颌、发际线和年龄观感，再独立检查环境融合。传入参考或哈希通过不能当作视觉验收通过。不像或无法判断则退回重做，不进入待发成品。单图失败不改身份包；换账号必须重新读取该账号包，不使用上一账号的图。已有有效身份文件时不得要求用户重复上传。
