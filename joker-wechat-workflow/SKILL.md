用户本轮限定优先于默认：说“不生成配图”则跳过生图，继续完成正文、标题、摘要、排版和归档；不等于自动取消草稿保存。可使用当前稿已确认且适配的图片，不能随意拿其他文章封面凑数。若缺少后台必填封面而无法保存，交付已完成成品并明确“待补封面后保存”，留下续接记录，不让正文工作停摆。说“只写正文”则按明确终点停止；说“不保存草稿”则只交付本地成品。WorkBuddy 等 Agent 同样遵守，能力不可用时记录真实缺口，不能把缺图、未保存当作全流程完成。

一次要求多篇时，各篇分别完成配图、固定排版、保存和回读，逐篇报告结果；不自动合并成一个多篇消息。已定账号沿用角色合同、认可正文和文风参照，不重新定位；必须逐篇实际审稿，不能承诺仅凭 Skill 就让任意模型百分之百复制文风。

### 文章模式固定交付

1. 选题卡与素材状态。
2. 一个定稿标题、摘要和最终正文。
3. 事实账本、角色风格验收和脚本检查结果。
4. 按账号规则制作并验收的封面；正文是否配图由账号配置和内容需要判断。人物、场景和尺寸必须通过门禁。
5. 使用该账号固定样式生成可复制富文本与移动端预览，不得只交 Markdown 正文。
6. 内容卡、资产清单、当前状态和角色知识回流记录。
7. 默认保存到公众号草稿箱并重新打开核验；用户明确取消时交付本地可复制发布包。后台受阻则交付已完成部分并明确未保存原因，不能把本地完成当成默认终点。

文章的详细制作、人物一致性、封面尺寸、排版及草稿门禁见 [article-production-rules.md](references/article-production-rules.md)。选题、写作和标题阶段分别按 [topic.md](references/modules/topic.md)、[writer.md](references/modules/writer.md)、[title.md](references/modules/title.md) 执行。这些是内部模块，不是用户入口。

### 贴图模式固定交付

1. 选题卡和一个定稿标题。
2. 最终短正文；账号采用文字卡时另有分页文案，照片型贴图不强制叠字或分页说理。
3. 按当前账号形式实际制作的全部有序图片：照片型采用生活照、场景或风景照，文字卡型检查手机可读性；不得只交文案、提示词或单张示意图。
4. 可编辑源文件、事实账本、角色风格验收、图片与分页验收记录。
5. 内容卡、资产清单、当前状态和角色知识回流记录。
6. 默认使用公众号原生贴图入口保存并重新打开核验；用户取消保存时交付本地上传包。后台受阻如实记录缺口。

文章和贴图独立选题、独立制作、独立记录，也可按用户要求同题制作或将已确认文章转换为贴图；不要求必须配套或必须换题。用户要求官方文章转贴图时先检查后台实际转换入口及结果，转换后核验图片、文案和顺序；不凭推测宣称已完成转换。

贴图的详细制作和人物一致性规则见 [card-production-rules.md](references/card-production-rules.md)。其选题和标题仍读取内部模块，不要求用户另行调用任何 Skill。

### 新账号建档固定交付

建立独立账号目录和配置，至少包括：账号ID与名称、目标读者、角色定位与事实边界、内容范围、文风锚点、视觉身份包、场景登记、封面规格、排版模板、发布权限、知识回流路径和当前进度。已有信息直接写入；只有影响后续成品且无法从用户材料判断的关键字段才集中询问。建档完成后，后续文章和贴图都继续调用本 Skill。

视觉部分按 [account-visual-setup.md](references/account-visual-setup.md) 建立每角色独立配置与记录。不能只建立人物名字就标记建档完整；身份、场景等缺失要按实际状态处理，不能复制其他角色内容填空。

## 内部阶段的职责

- **选题模块**：从账号范围、现有材料、对标和近期内容中选出一个具体题目，防止重复和无来源扩写。
- **写作模块**：按当前角色合同和认可样文写正文，建立事实账本并验收角色声音。
- **标题模块**：从最终成稿提炼能兑现的标题，不用夸张承诺反向改造正文。 下班写真馆按标题模块的账号专属规则，先比较高阅读对标钩子，再组织正文并校验兑现；不沿用默认的成稿后提炼顺序。
- **贴图模块**：完成分页文案、实际图片、短正文、可编辑源和移动端验收。

这些模块用于维护、排错和在总流程内部按需加载。对用户只呈现本 Skill 的模式和最终成品，不要求用户决定该调用哪个模块。

## 完成状态

内部审稿按 `references/modules/writer.md` 合并为一轮，有实质问题才修改。对短文，内容卡可用一段汇总方法、标题兑现和修改点；两份机器校验文件由同轮判断生成，不重复写六份报告，也不每篇重新研究全部资料。

面向用户只交付成品：账号、定稿标题、简短摘要、成品预览入口和草稿保存结果。多篇用简短列表逐篇呈现；正文可在成品预览完整查看，用户要求时直接展示全文。JSON、事实账本、内容卡、工具日志和验收数据是项目内部文件，后台维护和知识回流仍需完成，但不得将这些文件列表作为主要交付甩给用户。必要缺口只说明影响和下一步。

每次结束只允许使用与证据相符的状态：

- `可复制发布包完成，后台未保存`
- `贴图上传包完成，后台未保存`
- `公众号草稿已保存并回读通过`
- `已保存，待回读`
- `保存结果未知，待对账，禁止重复创建`
- `保存失败（有明确未创建证据）`
- `待修订：<具体未通过项>`
- `按用户要求提前停止：<已完成>，<后续待做>`

本地文件、脚本 PASS 或浏览器页面可见都不能替代公众号草稿回读；没有发布不得写已发布，没有真实数据不得填写阅读量。所有成品与记录必须进入当前账号项目，不只留在临时目录、Downloads 或生成工具默认目录。
