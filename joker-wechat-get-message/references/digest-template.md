# 逸尘群聊解析模板（对照，不安装其 Skill）

`yichen-wechat-local-vault` 的群聊解析不是一份单独的 HTML 皮肤，而是两层：

1. **`wechat_digest.py`**：按监控名单把各会话消息裁切成日报 Markdown（概览表、活跃排行、按会话堆时间线）。这是素材/流水，不是成品简报。
2. **真正给读者看的「群聊精华」**：来自它吸收的宝玉工作流。先 `digest-source` 把消息落到群目录，再按固定章节写成简报。

本技能 **不装 yichen、不用 wx-cli、不抓密钥**。下面只复用第 2 层的章节顺序，用来写私人本机报告里的叙事；主交付仍是已确认的 HTML 模块。

## 成品简报骨架（采用）

```
{群名} 群聊精华 · {日期或日期区间}

{开篇 1–2 段散文，无小标题：先写本期最有辨识度的一条线}

{emoji} {话题分类名，禁止叫「讨论」「闲聊」}

{该分类下合并后的叙述 / 「」原话 / 谁说了什么}

今日待解决问题   ← 没有真实未解问题整段省略
问题：…
提出者：…
背景：…
状态：✅ 已解决 / ⚠️ 部分解决 / ❌ 仍未解决
方案：…

📊 消息统计: 共 N 条消息
⏱ 覆盖区间: MM-DD HH:MM ~ MM-DD HH:MM
1. {昵称}: N 条
…

群友画像          ← 本期发言 ≥3 条的人；私人本机可写可读名
{昵称}（{本期角色标签}）
• {有证据的观察}

本简报由 AI 自动生成
```

## 明确不采用

| yichen / 宝玉做法 | 原因 |
|---|---|
| 毒舌版 / roast | 未要求；红线多，默认不做 |
| @bot 答疑 | 本快照流程没有群内 bot |
| 无 Markdown 纯文本（不用 `#`、`**`） | 我们主交付是可搜索 HTML |
| `history.json` 只记 `MM-DD HH:MM` | 跨年比较会坏；继续用现有消息身份差集 |
| frida 抓 key、增量解密活库 | 交接禁止 |
| 把监控名单当实时监听 | 名单只决定「下次整理谁」，要你开口才跑 |

## 和现有 HTML 怎么对齐

已有 `群聊精华.html` / `详细报告.html` 的模块保留：概览、数据概况、热门话题、重点讨论、干货、变现、工具、行动清单、来源索引。

写的时候把逸尘骨架嵌进去，而不是另出一套主报告：

- 开篇散文 → 概览里的核心摘要
- 话题分类名 → 重点讨论的条目标题
- 待解决问题 → 重点讨论里的「未解问题」，没有则不单开
- 发言排行 / 群友画像 → 私人本机可折叠次要区；公开分享版仍默认匿名排行
- 统计口径继续以 SQLite 为准，不目测

联系人不用群日报。见 `report-format.md` 的对话复盘顺序。
