# 质量标准

## 总体原则

**宁缺毋滥，质量第一**

- 抽取的每条内容必须有独立价值
- 文章必须完整、准确、可读
- 分类必须正确
- 格式必须统一

---

## 群聊精华质量标准

### ✅ 合格标准

**内容质量**:
- [ ] 有明确的主题和价值
- [ ] 上下文完整，能独立理解
- [ ] 包含可操作的信息或深度洞察
- [ ] 对未来有参考价值

**格式质量**:
- [ ] 文件名格式正确（YYYY-MM-DD.md）
- [ ] 有完整的 YAML frontmatter
- [ ] 主题之间用 --- 分隔
- [ ] 代码/命令/链接原样保留
- [ ] 重要金句用 blockquote

**示例**:
```markdown
## Claude Code 隐藏命令

> 按 Esc 两次可以回退上一步操作，非常实用！

这个技巧在写代码时很有用，特别是当你走错了方向想撤销的时候。比 git reset 更灵活，而且不改变文件状态。学会了之后，我发现开发效率提升了不少。
```

---

### ❌ 不合格标准

**内容问题**:
- ❌ 单条孤立消息（"我用 X"）
- ❌ 缺少上下文（"这个命令很好用"）
- ❌ 纯表情或单字回复
- ❌ 闲聊水群内容
- ❌ [图片] 占位符

**格式问题**:
- ❌ 文件名格式错误
- ❌ 缺少 frontmatter
- ❌ 代码/命令/链接被修改
- ❌ 主题之间没有分隔符

---

## 公众号文章质量标准

### ✅ 合格标准

**Front 质量**（8 个字段）:
```yaml
---
source: 笔记同步助手/YYYY-MM-DD/<原文件名>.md  # 必需
author: <作者>                                   # 必需
original_url: <原文 URL>                        # 必需
saved: <抓取时间>                               # 必需
extracted: <今天>                               # 必需
category: <6 分类之一>                          # 必需
tags: [精华文章, <主题 tag>]                    # 必需
quality: ⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐        # 必需
---
```

**内容质量**:
- [ ] TLDR 3-5 句话，能快速了解文章核心
- [ ] 核心观点 3-5 个，独立成行
- [ ] 有值得记住的金句（原文引用）
- [ ] 原文全文完整，不截断
- [ ] 保留所有图片链接（`![](...)` 格式）
- [ ] 移除广告和导流二维码

**分类质量**:
- [ ] 分类正确（6 大分类之一）
- [ ] 按优先级匹配（Agent 技术 > AI 工程实践 > ...）
- [ ] 不创建新分类

**示例**:
```markdown
## TLDR
这篇文章介绍了 Claude Code 的 10 个隐藏命令，包括 /btw（并行插话）、/rewind（回退代码和对话）、/insights（使用习惯分析）等。这些命令能大幅提升开发效率，特别是 /btw 和 /rewind 在长会话中非常实用。建议每周跑一次 /insights 来优化自己的使用习惯。

## 核心观点
- Claude Code 的更新速度极快，很多功能在更新日志里看不到，需要关注开发团队的 Twitter
- /btw 命令可以在不中断当前任务的情况下插话问问题，避免上下文污染
- /rewind 可以分别回退代码和对话，非常适合做实验和尝试不同方案

## 值得记住的金句
> 按两下 Esc 可以回退代码，这玩意儿确实就是很多设计软件里面的 Ctrl+Z
```

---

### ❌ 不合格标准

**Front 问题**:
- ❌ 缺少必需字段（author, url, category 等）
- ❌ 字段值错误（如 extracted 日期不对）
- ❌ 分类错误或不属于 6 大分类

**内容问题**:
- ❌ TLDR 过于简短或过于冗长
- ❌ 核心观点少于 3 个或超过 5 个
- ❌ 原文被截断或摘要化
- ❌ 图片链接丢失或被修改
- ❌ 保留了广告或导流内容

---

## 质量评级标准

### ⭐⭐⭐ 三星（合格）
- 基本符合质量标准
- 内容有价值但不够突出
- 格式基本正确
- 分类准确

**适用场景**:
- 一般技术文章
- 常规经验分享
- 基础工具介绍

---

### ⭐⭐⭐⭐ 四星（优秀）
- 完全符合质量标准
- 内容有深度和洞察
- 格式完美
- 分类准确
- 有实践价值

**适用场景**:
- 深度技术文章
- 独特的观点或方法
- 实战经验总结
- 高质量的产品测评

---

### ⭐⭐⭐⭐⭐ 五星（精选）
- 内容质量极高
- 有重大启发或突破性观点
- 格式完美，可作范例
- 分类准确
- 极具收藏和参考价值

**适用场景**:
- 行业前沿洞察
- 颠覆性方法或工具
- 深度思考和总结
- 必读的经典文章

## 质量检查流程

### Step 1: 自动检查

使用脚本检查：
```bash
# 检查 frontmatter 完整性
python scripts/check_frontmatter.py <file>

# 检查格式规范
python scripts/check_format.py <file>

# 检查分类准确性
python scripts/check_category.py <file>
```

### Step 2: 人工审查

**群聊精华**:
- 每个主题是否有价值？
- 上下文是否完整？
- 格式是否正确？

**公众号文章**:
- TLDR 是否能快速了解文章？
- 核心观点是否准确？
- 原文是否完整？
- 分类是否正确？

### Step 3: 质量评级

根据内容质量和价值，给出 ⭐⭐⭐ - ⭐⭐⭐⭐⭐ 评级。

## 常见质量问题

### 问题 1：内容过于碎片化

**表现**: 每条消息都抽取，导致质量参差不齐

**解决**: 宁缺毋滥，只抽取完整的知识点

---

### 问题 2：文章内容不完整

**表现**: 只读前 50 行，导致内容截断

**解决**: 必须读取完整文件内容

---

### 问题 3：图片链接丢失

**表现**: 过滤或替换图片链接

**解决**: 保留所有 `![](...)` 格式的图片链接

---

### 问题 4：分类错误

**表现**: 没有按优先级匹配，导致分类错误

**解决**: 按优先级：Agent 技术 > AI 工程实践 > AI 产品 > AI 商业 > 知识管理 > 工作流

---

### 问题 5：格式不统一

**表现**: 不同文章的格式不一致

**解决**: 使用统一的模板和格式规范

---

## 质量改进建议

### 定期审查

- 每周检查一次处理结果
- 发现问题及时修正
- 总结经验，更新规则

### 用户反馈

- 收集用户对质量的反馈
- 根据反馈调整规则
- 持续优化流程

### 自动化提升

- 增加自动检查脚本
- 减少人工错误
- 提高处理效率

## 质量指标

### 关键指标

- **完整率**: 文章内容完整的比例（目标: 100%）
- **准确率**: 分类准确的比例（目标: >95%）
- **有效率**: 抽取内容有价值的比例（目标: >90%）
- **格式规范率**: 格式正确的比例（目标: 100%）
