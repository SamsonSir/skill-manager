# 创作样例与对照评测

当任务涉及风格匹配或连续内容生产时读取。普通单条写作无需建评测工程。

## 样例选择

先使用用户给出的、已认可的样例；没有时从获准来源选候选并标为待验证。不要因用户发来一篇文章就视为认可其所有风格。少量、相关、理由明确的例子比大量全文更有帮助。近期素材用于判断时效，旧素材可以学结构但不是今日热度证据。

样例卡保存：来源和日期、目标受众、用户认可/候选/合成演练状态、可借鉴特征、不能照搬的内容、素材使用范围。优先描述方法，避免复制第三方完整作品或独特表述。

每条创作输入只带：当前目标与授权引用、这条内容的证据、所需素材、相关样例卡、交付形式。用户允许 Agent 决定定位时，提出并执行可逆实验，不重复索要定位问卷。

## 两个合成演练样例（不是用户认可的风格）

假设素材：一个演示工具把12项待办整理成清单，但遗漏1个负责人；尚无真实企业节省工时证据。

候选A：屏幕先展示清单，“12件事排好了，但这里少了一个负责人。把原始记录和清单放在一起核对，漏项就出来了。” 接着展示补全结果。可借鉴：结果先出现，缺陷具体，结论有边界。不能宣传为企业实绩。

候选B：“你要的是一份能执行的清单。谁来做、何时交、交什么，这三项至少得对上。” 随画面逐项核对。可借鉴：表达紧凑，每句配一个信息动作。不能把三项当作所有业务的完整规则。

反例：“这款神器彻底改变工作方式，所有任务一键完成，每天省两小时。” 问题：没有依据的能力与收益承诺，缺少真实过程。

真实用户认可的样例一旦可用，优先替代合成演练样例；不要把候选写成账号定位或长期用户偏好。

## 可重复的对照流程

- 固定同一 brief、来源和输出限制，分别使用旧指令与候选指令；记录模型、指令版本与可取得的耗时/调用消耗。缺失数据不估算成已测结果。
- 用另一个不参与修改的案例作保留样本；不要只在写过样例的题材上得出结论。
- 先查硬条件：事实支持、素材范围、所需交付是否完整、授权是否越界。任一失败不能靠文风评分抵消。
- 再比较：开头可理解、信息重复、画面与文案对应、修改量。盲评时隐藏版本名称。模型评审只作辅助，不冒充用户偏好或观众反馈。
- 没有可辨差异就保留简单版本，不为优化而加规则。记录有效改动及适用范围，生产在途作品不换指令。

离线脚本评测通过不等于发布后有效。平台效果需比较相同观察年龄与接近题材的多条作品，并保留口径；不拿单条爆款证明 Prompt 导致增长。
