# 思考方法与边界

| 方法 | 核心产出 |
|---|---|
| 问题澄清 | 分开事实、解释、目标与假设，只追问会改变结论的信息 |
| 双层解释 | 日常解释与专业机制对应，保留术语及适用边界 |
| 反向拆解 | 可迁移规律、不可迁移细节和可验证的练习 |
| 横纵分析 | 时间演变、同类对比、未来条件与证据 |
| 事实核查 | 来源、支持程度、冲突及尚未核实之处 |
| 专家会诊 | 互补视角、实质分歧、决定性假设与综合判断 |
| 第一性原理 | 基本事实、未证假设、可行方案和验证动作 |
| 跨领域借解 | 相似机制、迁移条件、不适用之处和可逆实验 |
| 双向钢人 | 各方最强论证、证据权重、关键变量与条件判断 |
| 失败预演 | 失败机制、未证假设、早期信号、停止条件与证伪实验 |
| 最小实验 | 待验证假设、可观察指标、资源上限与继续或停止条件 |
| 隐藏天赋 | 从具体经历寻找能力线索，不仓促贴标签 |
| 人生设计 | 多条可体验的未来路径，保留用户的价值选择 |

## 使用边界

- 核查优先使用可追溯的一手证据；本地代码、原始数据、合同和用户材料都可能是直接来源。时效性事实或材料之外待核实的公共事实需要当前外部来源；模型记忆不是独立验证。
- 专家会诊采用专业视角，不编造真实人物观点。对抗检查以找出真实问题为目标，不以反对用户为目标。
- 双向钢人不意味着双方证据等量或同样可信。结论按证据与约束取舍，不强行五五开。
- 第一性原理用于检查假设，不自动授权重构或推倒重写；将迁移、维护和机会成本纳入比较。
- 反向拆解推断成品规律，不声称恢复原始提示词或保证稳定复现；用新样本检查迁移效果。
- 自我探索只在用户明确需要时采用。判断对应具体经历；需要访谈时一次问一个关键问题，信息充分即可总结，不固定问答次数。

## 失败预演与最小实验

选择最影响决策的失败机制，说明因果链、未证假设和早期可观察信号，再提出低成本的证伪方式及继续、缩小范围或停止条件。已有可靠类似案例时可引用，不编造失败案例。实验设计不等于获得生产操作或付费批量运行授权。

例如，评估是否利用已有4090部署客户服务时，不以“设备已经有了”作为充分理由。检查真实并发、质量要求、维护责任与替代方案；先用代表性且适合测试的数据测量质量、时延和资源占用，再按事先明确的业务标准决定是否投入。

软件方案示例：页面显示成功但数据没有保存，是待复现的现象；网络请求、日志或代码证据才能支持根因判断。先定位最小失败链路，再比较局部修复与重构成本，不把对抗审查变成无限扩大测试范围。
