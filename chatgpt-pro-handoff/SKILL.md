# ChatGPT Pro 分析 → 添加到 Codex → 验证实施

## 来源与边界

依据：[卡兹克原文](https://mp.weixin.qq.com/s/abqrwY1T1WieYW5xDFKRRg)。2026-09-17 已通过 wechat-article-extractor 读取完整正文。
文章核心：GitHub 提供代码和 PR 历史；私有只读 MCP 提供真实业务数据；在 Codex 快速聊天选择 ChatGPT Pro 并挂载这些连接器分析；将对话添加到 Codex；由 Codex 验证、实施、按授权上线。
作者使用飞书 OAuth、GPT-6 Pro 和 Astra high；这些是文中实例，模型可用性、权限和界面应实查，不能编造、静默替换或承诺额度与绝对稳定性。
GitHub 上传询问和分支同步检查是用户明确补充的执行要求。文章不要求 Cloudflare、Tailscale 或特定云厂商，不擅自引入这些设施。不要恢复已移除的网页模型反代、C2C 自动聊天协议或本地 Bridge。

## 入口与接续

- “按公众号方案分析当前项目”“使用本技能会诊”：从步骤 1 开始，连续执行到需要用户实际操作或真正缺失的授权处。
- “执行添加到 Codex 的方案”：确认导入内容与项目后从步骤 6 开始，不强迫重新分析或重新配置连接器。
- 新旧会话均读取当前版本技能和实际项目状态，不沿用旧对话里的临时 URL、旧工具路径或未经核实的完成结论。旧会话若仍选择已删除的 Web 模型，先明确需切换可用原生模型，不能承诺技能可修复启动前的模型路由故障。
- 在正常交付中记录当前步骤、目标仓库/分支/提交、已验证证据和唯一待办；不得把令牌、密钥或完整日志写入接续记录。需要持久化时遵守本机治理要求。

## 1. 确认目标与 GitHub 真实状态

确定具体项目和分析目标；父目录包含多个仓库时逐项目识别，不能把整个工作区一键上传。
检查 Git 根目录、工作树改动、当前分支、remote；用 GitHub API/CLI 或远程引用实查仓库归属、可见性、分支与提交。remote 字符串或过期 remote-tracking 引用不是证明。
第三方 upstream 不等于用户自己的项目；区分作者代码和本地改造。只有需要分析的版本已在用户指定的 GitHub 仓库/分支中才进入步骤 3。

## 2. 缺少仓库或版本：准备后询问，获准后上传并接续

没有用户项目的 GitHub 仓库时，必须暂停上传和依赖它的分析，明确询问是否上传，不能直接宣布无法继续或绕去建隧道。
先完成可读审查：拟用账号、仓库名（默认私有）、目标项目、上传文件范围、忽略规则、密钥/凭据/个人与业务敏感数据、体积异常文件。不要展示秘密内容。再给出具体问题：
“当前项目尚未在你的 GitHub 上。是否将【项目】上传到【账号/仓库】的私有仓库？上传范围为【代码和必要文档】，排除【凭据、运行数据等实际项】。”
已有仓库但有需分析的未提交/未推送内容时，同样展示具体分支与差异范围，询问是否提交并推送这些变更；已有授权覆盖这些操作时不重复问。
- 同意：复用 gh/git 登录，必要时引导用户认证；完善忽略规则，核对实际暂存 diff，按授权初始化/创建私有仓库或复用目标仓库、提交、普通 push；不强推、不把无关改动混入、不删除用户改动。远端领先时先检查并安全整合，不能覆盖远端。
- 拒绝：保留本地成果，说明流程停在 GitHub 数据准备，不能宣称已分析当前本地版本；用户明确选择旧远端版本时才可按该范围继续。
- 推送后：远程读取分支 SHA 与本地待分析提交比较，并读取至少一个代表性文件验证内容；然后自动继续步骤 3，不再问“要不要继续”。

## 3. 连接 GitHub 与按需连接真实业务数据

本机 gh 登录不代表 ChatGPT 已授权 GitHub。复用 ChatGPT 已有 GitHub 连接；缺少连接或仓库权限时引导完成一次授权，限定所需仓库，并验证 ChatGPT 能实际读取目标内容。不要每次会话都创建连接器。
判断问题是否需要日志、事件、线上数据库、成本/性能指标：
- 代码/架构问题：使用代码与 PR，明确无生产数据证据，不为凑步骤虚构 MCP。
- 降本、性能、线上故障等依赖真实业务数据的问题：保留文章的只读 MCP 分支，不得以 GitHub 代码代替真实运行数据。优先复用现有业务数据连接器。
- 缺少必要 MCP：明确数据位置、归属、授权与现有认证方式，准备最小只读接入方案后按任务授权实施。需要部署资源或额外权限时提出具体缺口，不擅自换云服务、打开隧道或暴露本地端口。
- MCP 要求最小权限、只读、审计、脱敏、查询范围/时长/结果数限制，避免影响生产性能；私有数据通过 OAuth 等实际支持的认证保护。飞书认证仅在用户已有且适用时复用。
- 验证未授权请求拒绝、授权查询返回真实数据、接口无写能力、敏感字段不泄露、查询开销受控；公网可达或 tokenCount 非零不等于 ChatGPT 已成功读取。

## 4. Codex 快速聊天：选择 Pro、挂载连接器、分析

给用户一次性完整操作：Codex 左上角“快速聊天” → ChatGPT 聊天窗 → 选择账号实际可用的 Pro 模型 → “+”选择 GitHub，若步骤 3 要求业务数据则同时选择该私有 MCP → 发送已准备的分析提示词。
用户手动操作 ChatGPT；不以 Skill 名称当 ChatGPT 可调用功能。禁止自动控制 ChatGPT 是本技能沿用的交互选择，不是文章宣称的强制要求。
提示词须填实：项目/仓库、分支/PR、已同步提交、目标、约束、所需数据与时间范围。要求先报告读到的仓库、文件、PR 和业务数据样本，再以证据分析，输出收益、风险、实施顺序、目标文件、验收方法及上线/回滚条件；不足处标注，不能把猜测当生产结论。连接器不能定位分支/提交时明确未验证，不谎称精确版本审查。
等待 Pro 完整结果；思考时间不固定。已授权 GitHub 且内容可读时直接继续，不再停在“你有 remote”。失败时定位权限、索引、连接器或数据缺口，保留有效结果，不能循环建 tab、重发分析或重新安装旧桥接。

## 5. 添加到 Codex

分析结束，用户点击聊天窗口“添加到 Codex”，保留完整上下文；不要求下载再上传方案文件。
明确执行提示词：“帮我验证，并且做掉这里面提到的所有值得做的优化，然后统一上线。”仅在用户确实要求上线时使用末句；否则改为“实施并验证，暂不上线”。
执行模型按文章使用原生 Codex Astra high 的角色分工；核对实际可用选项，不能自行更改用户模型或把某个显示名称视为模型身份证明。
验证导入后的任务确实有方案正文/关联上下文、目标仓库和分支。无法观察用户导入结果时停在“等待添加到 Codex”，不能自行创建新任务代替导入或报全链路通过。

## 6. Codex 验证、实施、上线与收尾

逐条核对建议与当前代码/数据，识别分析后发生的版本变化；采纳有价值的优化，修正过时或无依据的建议，解释未采用项。
在原有授权范围内持续实施，保留无关改动；完成与行为相关的测试和用户路径验证。上线已明确授权则完成部署、线上健康与效果验证以及必要回滚检查；无上线授权则交付可审核成果，不擅自发布。
无需返回 ChatGPT 重跑旧 C2C 评审循环。记录文件、diff、执行结果与证据，不把“代码改完”当验收。

## 完成标准与真实限制

阶段必须依次有证据：
1. GitHub 目标仓库和所需版本存在，或用户明确批准只分析指定旧版本。
2. ChatGPT 已实际读取所需代码与 PR；PR 不存在则注明无历史，不能伪造。
3. 依赖生产数据的任务已读到真实数据并验证权限；纯代码任务注明不适用。
4. Pro 已给出基于这些证据的完整分析方案。
5. 对话已添加到 Codex，目标和上下文齐全。
6. 建议已核验，实施和必要测试完成；包含部署时线上验证完成。

缺少任何适用项，只能报告已完成阶段与具体剩余项。GitHub 路线消除了对本机临时隧道的依赖，但不能保证服务、账号、索引、新旧会话永不失败。跨会话验收需实际新会话/旧会话读取并完成交接，静态技能检查不能冒充该实测。
