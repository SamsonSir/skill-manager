# 有证据的工作流改进

先解决当前任务，再判断是否值得沉淀。优先最小修正，不把每次失败变成新的全局禁令。

## 选择与归属

- 捕获有后续价值的决定、承诺、状态变化、稳定偏好、可复用成果或重要冲突；临时错误恢复后可只留本次任务证据。
- 涉及长期状态、跨 Agent 或正式知识写入时，先读当前环境的知识治理规则；归属不明不正式写入，个人与客户资料隔离。
- 查找同一问题的已有记录，更新原记录而非重复建库。使用项目现有记录位置，不强制创建 .learnings、OpenClaw 工作区或 hooks。
- 区分用户决定、AI 假设、已执行与已验收。记录来源会话、日期、适用范围、原始证据定位和替代关系；不保存完整会话、密钥或敏感工具输出。

## 修正与验证

1. 从原始证据判断根因：规则、上下文、工具、数据或业务假设，不能一律归因于 Prompt。
2. 定位实际生效文件；共享规则只维护一处，客户端入口引用或由既有生成器维护。
3. 删除重复职责或修正具体冲突，保留真实权限与项目验收；不自行增加目标、预算或对外权限。
4. 用代表性请求和独立保留样本检查新行为；区分结构验证、行为演练与生产验证。
5. 保存可回滚版本，只将验证有效且适用范围清楚的改进用于新任务；长期运行中的任务先核对其版本与协作边界。

重复次数是排查线索，不自动授予写入全局规则的权限。不要为了记录错误而中断已授权工作，也不要自动安装或开启 hooks、定时器、遥测和跨会话群发。
